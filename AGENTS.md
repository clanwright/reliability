# Reliability project

This project uses upstream Restic and the built-in NixOS `services.restic.backups` module. Prefer ready-made modules; use Nix for configuration. Do not reintroduce a custom executor, recovery-unit schema, runtime orchestration scripts, or compatibility wrappers for the retired `clanwright.reliability` interface. The lead owns architecture, integration and delivery; workers edit only assigned files. Provider, secret, deployment, real backup, restore and prune operations require explicit owner authorization. External Apps and Primitives implementations must not be inspected or changed.

No secret values, provider account names, real machine topology or credentials in code/docs/test output. Use fake data for tests. No remote/provider operations from workers. Never delete real backup data. Preserve test evidence under ignored .work. Test the canonical NixOS example and real Restic on temporary local repositories. File backup and repository checks do not establish database consistency or semantic application recovery. Target Linux services and macOS local tooling. No hosted CI or virtual-machine/QEMU tests; use local checks and documented Linux builder when needed. Documentation index is README.md; commands belong in docs/operations.md.
